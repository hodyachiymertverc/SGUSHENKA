# Защита паролей и ключей (firebase-config.js, admin-config.js)

Сайту нужны два «секретных» файла, чтобы работать:

- **`firebase-config.js`** — ключи твоей базы Firebase (лежат в облаке).
- **`admin-config.js`** — пароль от админ-панели.

Оба файла уже лежат рядом в архиве и сайт с ними полностью рабочий
"из коробки". Но чтобы они **не попали в публичный репозиторий на
GitHub**, если ты решишь выложить проект туда, сделано следующее:

- Оба файла добавлены в `.gitignore` — если ты инициализируешь git и
  сделаешь `git add .`, эти два файла Git просто проигнорирует и не
  закоммитит.
- Вместо них в репозиторий коммитятся шаблоны-примеры
  `firebase-config.example.js` и `admin-config.example.js` — с
  плейсхолдерами вместо настоящих значений, их можно спокойно
  публиковать.

## Как это работает на практике

### Вариант 1 — просто открываешь index.html локально / грузишь файлы вручную на хостинг
Ничего делать не нужно — `firebase-config.js` и `admin-config.js` уже
на месте с рабочими значениями. Просто не выкладывай их в открытый
Git-репозиторий (см. `.gitignore` выше — если работаешь через git,
он и так их не закоммитит).

### Вариант 2 — деплой на GitHub Pages через GitHub Actions (рекомендуется)
В комплекте есть готовый workflow `.github/workflows/deploy-pages.yml`.
Он сам, прямо во время каждого деплоя, создаёт `firebase-config.js` и
`admin-config.js` из **секретов репозитория** — то есть реальные
значения вообще никогда не появляются в git-истории.

Настройка (один раз):
1. Создай приватный или публичный репозиторий на GitHub и запушь туда
   проект (файлы `firebase-config.js` и `admin-config.js` не
   закоммитятся благодаря `.gitignore` — это нормально).
2. В репозитории: **Settings → Secrets and variables → Actions → New
   repository secret** — добавь по одному секрету на каждое значение:
   - `FIREBASE_API_KEY`
   - `FIREBASE_AUTH_DOMAIN`
   - `FIREBASE_DATABASE_URL`
   - `FIREBASE_PROJECT_ID`
   - `FIREBASE_STORAGE_BUCKET`
   - `FIREBASE_MESSAGING_SENDER_ID`
   - `FIREBASE_APP_ID`
   - `ADMIN_PASSWORD`

   Значения для Firebase бери из своего `firebase-config.js` (или из
   Firebase Console → Настройки проекта). Значение `ADMIN_PASSWORD`
   — какой пароль хочешь для входа в `admin.html`.
3. В репозитории: **Settings → Pages → Source → GitHub Actions**.
4. Сделай любой `push` в ветку `main` (или запусти workflow вручную
   вкладкой Actions → Deploy to GitHub Pages → Run workflow).

После этого сайт опубликуется на `https://<твой-логин>.github.io/<репозиторий>/`,
а сами секреты будут видны только тебе в настройках репозитория — не
в файлах и не в истории коммитов.

## Важно понимать: реальные пределы защиты

- Это статический сайт **без сервера** — весь код выполняется в
  браузере пользователя. Значит, `firebase-config.js` и
  `admin-config.js`, какими бы «спрятанными» они ни были в
  репозитории, **всегда видны** тому, кто откроет уже
  опубликованный сайт и посмотрит исходный код страницы или вкладку
  "Сеть" в инструментах разработчика. `.gitignore` и секреты GitHub
  прячут их только из репозитория/истории git — не с самого
  работающего сайта.
- `apiKey` в Firebase — это, по документации самого Firebase, вообще
  не секрет: он специально виден в клиентском коде. Настоящая защита
  твоих данных (рекордов, никнеймов и т.д.) — это **правила Realtime
  Database** (Firebase Console → Realtime Database → Rules). Сейчас
  в проекте предполагается `{ ".read": true, ".write": true }` для
  простоты (без входа в аккаунт) — это означает, что писать в базу
  технически может кто угодно, кто найдёт твой databaseURL, а не
  только твой сайт. Если это важно — стоит на стороне Firebase
  ограничить запись (например, через Firebase Auth и более строгие
  правила), но это уже выходит за рамки простого статического сайта.
- Пароль админ-панели (`admin-config.js`) — это просто проверка "если
  строка совпала — показать панель", целиком на стороне браузера.
  Это отпугнёт случайных людей, но не защитит от того, кто
  осознанно откроет исходный код страницы. Для настоящей защиты
  панели нужен отдельный сервер с проверкой пароля — в этом проекте
  его нет.
- Если хочешь по-настоящему скрыть админку и данные — самый простой
  шаг: сделай репозиторий на GitHub **приватным**, а не публичным.
